# Rules

Every rule frostagent knows, with its default severity. A policy line `<subject> may <rule>` waives one; `forbid <rule>` raises one to a failure. Generated by `frostagent rules --markdown`.

## FAIL by default

### `plain-http`

A remote server is reached over plain http, so tool results and any token can be read or altered in transit.

**Fix:** Change the url to https. If the server is on this machine, use localhost, which is exempt.

### `plaintext-secret`

A token or key is written literally into a config file instead of referenced from the environment.

**Fix:** Replace the value with `${NAME}` and export NAME in your shell profile or secret manager. Rotate the token if the file was ever committed or synced.

### `secret-in-args`

A token is passed on the command line, where every process on the machine can read it.

**Fix:** Move it to `env` as `${NAME}`; most servers read a token from the environment.

### `remote-script-exec`

A command downloads a script and runs it in one step.

**Fix:** Download the script, read it, commit it, and run the committed copy.

### `hook-destructive`

An automatic hook can delete or overwrite data.

**Fix:** Scope the target to a build or cache directory inside the project, and never to a variable that can be empty.

### `hook-sudo`

An automatic hook escalates privileges.

**Fix:** Hooks run on every matching event with no prompt; they must not need root.

### `broad-permission`

A permission rule allows a whole tool without limits.

**Fix:** Scope it: `Bash(npm test:*)`, `Bash(git status:*)`, `mcp__github__get_issue`. Add one line per thing you actually pre-approve.

### `dangerous-permission`

A permission rule pre-approves a destructive or privileged command.

**Fix:** Delete the rule and answer the prompt when the command is needed.

### `hidden-unicode`

Invisible or direction-changing characters that can hide instructions from a reader.

**Fix:** Open the file in an editor that shows invisible characters and remove them. If you did not write them, treat the source as hostile.

### `skill-destructive`

A skill's commands can delete data or escalate privileges.

**Fix:** Restrict deletions to paths inside the project and never to a bare variable.

### `tool-poisoning`

A tool description contains instructions aimed at the model rather than a description of the tool.

**Fix:** Remove the server. A description that tells the model to call other tools, hide things, or send data somewhere is an attack, not a bug.

### `instructions-poisoning`

The server's initialize instructions, which the host hands to the model, contain steering text.

**Fix:** Remove the server. Instructions should describe how to use the tools, not override the user.

### `prompt-poisoning`

A prompt template's description or arguments contain steering text or hidden characters.

**Fix:** Remove the server, or the prompt if you control the server.

### `tool-drift`

A tool's description or schema changed since it was locked.

**Fix:** Diff the tool against the lockfile (`frostagent probe --verbose`). If the change is legitimate, `frostagent lock` to approve it.

### `server-credential-access`

A local server's source reads credential stores.

**Fix:** A server should receive one token through env, not read `~/.ssh`, `~/.aws` or the keychain.

### `tool-arg-shell`

A tool argument is interpolated into a shell command string in the server's source, so anything that steers the model can run commands.

**Fix:** Pass arguments as an array to spawn or execFile, never into a shell string. If the tool exists to run shell commands, say so: `server "name" may tool-arg-shell`.

### `tool-arg-eval`

A tool argument reaches eval or code compilation in the server's source.

**Fix:** Do not evaluate model-controlled text. If the tool is a code interpreter by design, sandbox it and record the exception in the policy.

## WARN by default

### `unpinned-package`

A server is launched from a package registry without a pinned version, so the next run may execute different code.

**Fix:** Add the version: `npx -y pkg@1.2.3`, `uvx pkg==1.2.3`. Then `frostagent lock` so the tools it exposes are pinned too.

### `unpinned-image`

A container image without a digest or fixed tag.

**Fix:** Use `image:1.2.3` or better `image@sha256:...`.

### `privileged-container`

A container runs with host-level access.

**Fix:** Drop `--privileged`, `--pid=host`, `--net=host`, and mounts of `/` or the Docker socket. Mount only the directory the server needs.

### `untrusted-location`

A server binary lives in a temporary or download folder.

**Fix:** Move it under a project or `~/.local/bin`, somewhere a download cannot silently replace it.

### `dangerous-flag`

A command disables its own safety checks.

**Fix:** Remove the flag, or record why it is needed with a policy line.

### `hook-network`

An automatic hook talks to the network, so tool input or output may leave the machine.

**Fix:** If the hook must send data, send only the fields it needs to a host you control, and name that host in the policy.

### `hook-eval`

An automatic hook evaluates text it received, which the model or a tool result controls.

**Fix:** Parse the JSON on stdin with jq and pass fields as arguments; never `eval` or `sh -c` with them.

### `permissive-mode`

The permission mode skips confirmation.

**Fix:** Use the default mode, or `acceptEdits` if only file edits should be automatic.

### `skill-directive`

A skill contains text aimed at steering the model against the user.

**Fix:** Read the quoted text in context. A skill should instruct the model how to do a job, never to hide something from the person.

### `skill-network`

A skill's commands reach the network.

**Fix:** Confirm each host is one the skill needs, then `skill "name" may skill-network` in the policy.

### `skill-secret-access`

A skill reads credential files or asks for secrets.

**Fix:** A skill should use a tool that already has access, not read `~/.ssh` or `~/.aws` itself, and should never ask the user to paste a key into the chat.

### `broad-skill-tools`

A skill is allowed an unrestricted tool.

**Fix:** List the specific tools: `allowed-tools: Bash(npm test:*), Read`.

### `tool-url`

A tool description names a URL, which is where data goes when a poisoned tool exfiltrates.

**Fix:** Check that the host is the server's own API. If the description also talks about sending data, treat it as tool-poisoning.

### `oversized-description`

A tool description is far longer than its peers, a common place to bury instructions.

**Fix:** Read the whole description. Long is fine; long with instructions to the model is not.

### `tool-shadowing`

Two servers expose the same tool name, so the model may call the wrong one.

**Fix:** Remove one server, or rename with the host's server prefix, and pre-approve tools by full name.

### `tool-lookalike`

A tool name is one edit away from another server's tool.

**Fix:** Check that the lookalike is not impersonating a trusted tool; remove the server if it is.

### `annotation-mismatch`

A tool claims to be read-only while its name says it writes.

**Fix:** Report it to the server author. Until fixed, do not pre-approve the tool on the strength of its hint.

### `resource-poisoning`

A resource description contains steering text or hidden characters.

**Fix:** Read the resource before letting the model use it; remove the server if it is hostile.

### `tool-added`

A server exposes a tool that is not in the lockfile.

**Fix:** Read the new tool, then `frostagent lock`.

### `probe-failed`

A server could not be started or did not answer.

**Fix:** Run the command by hand. A server that cannot start in frostagent cannot start in the agent either.

### `config-error`

A config file exists but could not be parsed.

**Fix:** Fix the JSON or TOML; the agent host is probably ignoring the file too.

### `policy-expired`

A policy exception has passed its date.

**Fix:** Fix the underlying finding and delete the line, or extend the date with a reason.

### `server-exec`

A local server's source spawns processes.

**Fix:** Expected for shell and git servers. Confirm and `server "name" may server-exec`.

### `server-eval`

A local server's source evaluates code at runtime.

**Fix:** Look at what feeds the eval. If tool arguments can reach it, the model can run arbitrary code.

### `tool-arg-exec`

A tool argument is passed to a spawned process in the server's source.

**Fix:** Expected for git and build tools. Check the argument cannot select the program itself, then allow it in the policy.

### `probe-side-effect`

A server created files under your home directory just by starting.

**Fix:** Read what it wrote. Config and cache files are common; a generated client id and remote feature flags mean telemetry. Decide, then allow it in the policy or drop the server.

## INFO by default

### `hook-external-script`

An automatic hook runs a script that lives outside the project.

**Fix:** Move the script into `.claude/hooks/` so it is reviewed with the repo, or `trust hook` it in the policy.

### `network-permission`

A permission rule pre-approves network access.

**Fix:** Fine if intended. Name the hosts in the policy so a new one is noticed.

### `skill-links`

Hosts a skill links to in prose.

**Fix:** Nothing to fix; this is the list a reviewer should glance at.

### `skill-exec`

A skill ships scripts or is allowed to run commands.

**Fix:** Read the scripts once; they run with your permissions.

### `exec-surface`

A tool takes a command, script or query as free text.

**Fix:** Expected for shells and databases. Make sure the host asks before running these tools, and `forbid exec-surface` in repos that should have none.

### `destructive-unmarked`

A tool that deletes or removes is not annotated as destructive.

**Fix:** Report to the server author; hosts use the hint to decide whether to confirm.

### `server-instructions`

The server sends instructions to the model at startup; read them.

**Fix:** Read them once; `frostagent lock` records them and reports any change.

### `tool-removed`

A locked tool is no longer exposed.

**Fix:** `frostagent lock` to update the record.

### `server-unlocked`

A server has no entry in the lockfile yet.

**Fix:** `frostagent lock` after reading its tools once. Add `require lock` to the policy to make this a failure.

### `server-network`

Hosts a local server's source connects to.

**Fix:** Confirm the hosts are the service the server fronts; name them in the policy.

### `server-env`

Environment variables a local server's source reads.

**Fix:** Pass only what it needs. A server that reads the whole environment sees every token you have.

### `server-fs-write`

A local server's source writes files.

**Fix:** Expected for filesystem servers. Check the paths are confined to the configured roots.

### `tool-arg-sql`

A tool argument reaches a database query in the server's source.

**Fix:** Expected for database tools. Make sure the host confirms these calls and the database user is read-only where it can be.

### `tool-arg-fs`

A tool argument selects a filesystem path in the server's source.

**Fix:** Expected for filesystem tools. Check the server confines paths to its configured roots.

### `tool-arg-network`

A tool argument selects a network destination in the server's source.

**Fix:** Expected for fetch tools. Know that the model can point it at internal addresses.
